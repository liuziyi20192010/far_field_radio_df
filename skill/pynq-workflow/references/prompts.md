# 可复用提示词工作流

以下是从工程经验提炼的后写模板，变量由新队伍替换，不是原始历史消息。`report/interaction/` 仅保留用户指定的“目前项目已经能够测量两路信号相位差”对话，不声称包含全部经验来源的原始消息。效果以工具输出为准，未做跨模型成功率评测。

## 需求到接口

```text
依据我的目标板卡、镜像与算法需求，提出 PS/PL 划分。
输入：{board_part_image}、{algorithm}、{rate_latency_budget}、{existing_bd_rtl_xdc}。
先列已确认与缺失事实，再给接口契约：寄存器、帧结构、单位、时钟域、reset、start/done、TLAST。
所有固定地址/位宽都需对应 HWH、RTL 或官方文档证据。
给独立黄金参考、有效性条件与最小数字通路自检，不用配置值充当实测结果。
```

## 根据失败分层诊断

```text
现象：{observable_failure}。附件：同一帧 {raw_intermediate_final}、包版本、manifest、工具输出。
找第一个与独立参考分歧的级；区分数据采集、CDC、运算、传输、软件与显示。
提出能区分假设的最小验证，运行后按证据修正结论。
保留失败日志和修改理由，不能把推断写成已证实实测。
```

## 优化与交付

```text
依据 {baseline_and_candidate} 的相同输入和 {resource_timing_latency_reports}，生成前后对比。
报告字段缺失时标未测；分别记录纯计算、传输/分配、端到端与 UI 刷新。
从空目录复现；遇到失败先保留日志，再修脚本并复验。
提炼与题目无关的 Skill，逐项写适用范围、调用方法、效果证据、失效条件与来源。
```

协作循环：需求→事实/契约→实现→工具验证→失败定位→最小修复→复验→记录。工程不需要训练本地模型或借用 3.1 的专用容器要求；本赛题是指南 3.3。
