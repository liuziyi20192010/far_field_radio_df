# 从实际失败提炼的定位清单

历史消息索引见 `report/interaction/sources.json` 与 `transcript.md`。下表的物理因果是工程诊断结论；历史主观反馈与当前仿真验证并列，不能单凭反馈推断全部板级问题已消除。

| 触发条件 / 现象 | 定位步骤 | 复用后的判断 / 边界 |
|---|---|---|
| 收 4K 点加 header，DMA 卡住 | 算实际 bytes；检查 BTT，TLAST、反压和 receive-before-start；记录 DMASR | 包头可能把长度推过默认边界；计数自检只证明数字通路 |
| 软件结果稳定，PL 结果跳动（9月26日） | 固定同一帧；比原始数据、PL 中间累加、乘法及最终结果；查 BIT/HWH/host hashes；查 I/O 寄存采样一致性 | 首个分歧级给出检查范围；单拍错位引起的相位只适用于已知采样率/频率关系 |
| 配置切换后 DAC 波形不一致（9月26日） | 给样本及 gain/enable 加同周期标签；查 apply/ack 时刻、输出饱和、IOB 与转发时钟 | 数据与控制流水线必须对齐；模拟阶梯/镜像不是自动证明 RTL 错误 |
| GUI 5秒刷新或旧任务干扰（9月27日） | 记录 capture/compute/render 时间；停止旧后台任务；一个物理 DMA 共享唯一所有者 | 降低绘图成本后仍需实测 FPS；帧间歇不能宣传为无间断采样 |
| 图中 12.5 MHz 峰丢失（9月27日） | 查看原始 FFT bin；画面下采样按频率区间保留 max，而非跳点 | 可保留尖峰，像素分辨率仍限制峰宽显示；不能替代频谱标定 |
| 端点角度或越界值错误（9月27日） | 写清物理模型及定义域；圆周误差与几何反三角函数分开处理；容差仅用于量化端点 | 不能把所有超界值 clamp 成端点；错误模型不会靠 UI 修好 |
| RTL 已改但板上仍是旧行为 | 显式重建 module-reference OOC，导出同一次 BIT/HWH/decoder，重启 kernel | manifest 是版本证据；检查不能自动刷新 manifest |
| 空目录从零构建 reset_run 报无匹配（本次） | 在 BD generate_target 后创建 IP run，再重置真实存在的 run | GUI 中曾有的任务不一定存在于 Tcl 创建的新工程；本次完整重建验证该修复 |
| 文档资源数与工具报告不同（本次） | 从原始 .rpt 提取数据，附路径与生成版本；未知字段保持未知 | 不把旧文字表当实测源；资源变化可能只是不同构建 |
| 校准仅报“需要有效且一致的帧”（10月25日） | 区分弱信号/OTR与原始累加、复乘、最终角度分歧；保存每次尝试的包、序号、接受状态和阈值差值 | 可在固定预算内补采瞬态坏帧；持续故障继续拒绝，不能用放宽阈值使校准通过 |
| RTL仿真通过，但DAC1无交流输出（10月25日） | 检查实际综合/路由网表的存储器地址与INIT；对实现后网表验证两路幅度、相位、时钟和禁用行为，并将成功证据绑定BIT哈希 | 本例共享双读ROM的CH1地址被固定为0，输出512；改用独立10点参考表。RTL与内部时序通过不能替代实现后功能验证；xsim断言失败也可能返回0，须核对真实成功标记 |
| 测量抖动小但稳定偏差突然变大 | 固定激励；分别确认两路真实输出、线缆插头、共地/同步参考、负载和量程；在相同接线条件重新校准后再多点记录 | 本例用户先报最大约5°，后确认同轴线松动，修复后观察约±1°；反馈不含原始帧，不能推断全部误差来源或拟合补偿。数字参考一致也不排除模拟输入问题 |
| 演示界面被调试数据淹没 | 保留主要测量量、应用场景及简洁有效性状态；耗时、中间量、原始数据和详细失败报告放维护入口/采集文件；核验简化界面后原有拒帧与模型边界仍生效 | 同一数据链路可支持演示和复验；大字体、平滑或隐藏诊断不证明准确性/FPS 改善。适配新项目时选择自己的核心量与物理边界 |

ADC/DAC 的 input/output delay 必须来自器件手册及板级延迟，不能为得到绿色 timing 报告猜值或扩大 false_path。零点校准可去固定偏差，不能修复 OTR、失配、丢样或随机抖动。

校准采集应先使旧零点失效，收齐有效帧且通过稳定性判断后一次提交新零点。补采预算按目标设备的误码/瞬态特征选择；本项目32个有效帧、最多8个拒帧只是实例。DMA、协议或配置异常立即退出，不当作普通信号坏帧重试。失败导出绑定本次校准报告，防止配置失败时把上次成功数据标成当前失败。离线注入验证了补采边界、持续不一致、OTR、传输异常和原始数据回放；尚无本次失败的真实板端包，不能据此宣称已经解决板级根因。
